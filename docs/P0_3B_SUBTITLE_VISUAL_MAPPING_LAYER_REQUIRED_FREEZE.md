# P0-3B-Reframe Subtitle Visual Mapping Layer Required Freeze

Status: Frozen

Scope: Documentation-only architecture reframe for P0-3B.

No runtime code changes.
No JavaScript changes.
No CSS changes.
No HTML changes.
No generated JSON changes.
No OCR implementation.
No AI coordinate extraction implementation.
No P0-3C implementation.

Repository evidence wins over chat memory.

## 1. Frozen Conclusion

P0-3B character-ratio marker positioning is not accepted.

The attempted P0-3B implementation must not be treated as the accepted final marker architecture.

Character-ratio marker positioning is not reliable for burned subtitles because burned white subtitles are pixels inside the MP4, not DOM text.

Text position is not the same as visual position.

## 2. Runtime Knowledge Boundary

Runtime currently knows obstacle text ranges through:

- `markerStart`
- `markerEnd`

Runtime does not know the real visual `x` / `y` coordinates of the burned English subtitle words.

Runtime must remain a read-only consumer.

Runtime must not perform real-time OCR during playback.

Runtime must not perform real-time AI inference during playback.

## 3. Required Mapping Layer

Burned subtitle marker alignment requires a text-to-visual-coordinate mapping layer.

The required mapping layer should connect:

- subtitle text
- obstacle `markerStart` / `markerEnd`
- real burned English subtitle visual coordinates

Future marker rendering should prefer visual mapping coordinates when available.

Character-ratio positioning may remain only as a fallback or debugging aid, but must not be considered the accepted production approach for burned subtitle markers.

## 4. Expected Mapping Data Shape

The mapping layer should eventually provide coordinate data such as:

- `subtitleId`
- `startMs`
- `endMs`
- English subtitle line `x1` / `x2` / `y1` / `y2`
- word-level or phrase-level `x1` / `x2` / `y1` / `y2`
- confidence score if OCR / AI is used

Generated coordinate data may eventually be stored as read-only data such as:

```text
output_text/visual_mapping/TBBT_S12E01_word_boxes.json
```

## 5. Offline Extraction Boundary

OCR / AI coordinate extraction, if used, belongs to an offline preprocessing pipeline.

Subtitle visual mapping data generated by OCR / AI must be exported as read-only JSON consumed by Runtime.

The architecture intentionally does not freeze any specific OCR engine or AI model.

Acceptable approaches include:

- OCR-based extraction
- vision-language-model-assisted extraction
- hybrid extraction pipelines
- human-assisted verification workflows

## 6. P0-3C Prototype Direction

P0-3C should be a small prototype, not full-episode production.

P0-3C prototype scope:

- current TBBT S12E01 video
- first 2 minutes only

Reason:

The first minute contains too few learning obstacles and is insufficient to evaluate the architecture.

P0-3C prototype goal:

Generate or simulate subtitle visual mapping data for the first two minutes and allow Runtime to render markers using the mapping layer.

P0-3C validation examples should include obstacles such as:

- `believe`
- `bedsheets`
- `outside`
- any other available obstacles within the first two minutes

P0-3C success criteria:

- markers appear below the burned white English subtitle line
- markers align visually to the corresponding word or phrase better than character-ratio positioning
- markers do not mislead the learner
- Runtime remains read-only
- existing obstacle count remains 48
- generated subtitle JSON and obstacle JSON are not modified
